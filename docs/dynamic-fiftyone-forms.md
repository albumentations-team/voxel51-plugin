# Dynamic FiftyOne Forms

VOX-13 renders transform input forms in FiftyOne from the albu-spec capability
catalog and neutral parameter schemas.

## Runtime Boundary

The FiftyOne host layer owns the UI mapping:

- `hosts/fiftyone/forms/augment.py` composes the operator form.
- `hosts/fiftyone/forms/renderer.py` maps `FormFieldSchema` to
  `fiftyone.operators.types`.

The renderer does not instantiate AlbumentationsX transforms. It only renders
neutral schema fields generated by the Albumentations backend.

## Field Mapping

The current renderer maps:

- `boolean` to FiftyOne `Boolean`
- `integer` to integer `Number`
- `float` to float `Number`
- `string` to `String`
- `enum` to `Enum`
- `number_range` to `Tuple(Number, Number)`
- `list` to `List`
- `json` to a JSON string input

Required complex fields that cannot be rendered safely are marked invalid and
read-only. Normal optional complex fields are rendered as JSON strings so they
remain editable without inventing transform-specific UI code.

## Execution Scope

This pull request changes the form layer. The execution path still uses the
temporary fixed-transform runner until the dynamic pipeline factory lands.

The fixed runner remains executable for:

- `HorizontalFlip`
- `RandomBrightnessContrast`
- `RandomCrop`

It accepts both legacy fixed-form names and new albu-spec names for the fixed
transforms where they differ.
